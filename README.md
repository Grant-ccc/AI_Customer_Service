# 花窗伞 AI 客服 MVP

基于花窗伞团购经历的客服产品实践，以第二轮团购为历史模拟场景。售前答疑为主，使用说明和人工交接为辅；不接真实支付、订单物流，不自动批准退款、换货或赔偿。

一阶段文字人工接待、AI自然回复、自动转人工、商家摘要与QQ接入已有实现；已有本机HTTPS公网试用，尚未完成正式生产部署。

2026-10-16 用户已确认[手机端 QQ 客服内测版交付范围](./docs/手机端QQ客服内测版_交付范围.md)：完成手机接待主流程、消息异常验证及内测启停与备份恢复。推送、过期补发、进度查询和结束结果登记暂缓。本轮尚未整体验收通过，结束接待不代表问题已解决。

2026-10-10 经用户审批回退旧AI方案后，已共同确认prompt、完成两轮离线验证，并按用户要求接入简化网页流程：完整prompt＋本轮对话生成自然回复，直接显示为AI助手消息；现已支持自动转人工与商家专用交接摘要，用户也可点击按钮转交，普通回复不使用候选审核队列、检索或分项JSON。已有聊天、账号、MySQL、本地Key与旧账本保留。详情见[简化AI网页接入说明](./docs/简化AI网页接入说明.md)。

## 本阶段目标

用户与商家共享同一会话：发送消息、主动转人工、商家查看和接手、在原会话回复、结束处理、后续再次咨询。桌面商家工作台采用三栏布局；移动端采用独立聊天页与交接详情面板，Android内测App加载商家网页。

身份、权限、持久化和未读状态由后端处理。AI回复使用固定官方deepseek-flash；等待人工与人工接待期间暂停，旧请求失效。人工结束后新咨询不携带上一轮模型上下文，页面历史保留。摘要仅商家可见，含用户诉求、已知情况、已尝试操作和材料情况，附原话依据；失败不阻止接手。

## 本地使用

本机已经准备项目内 MySQL、Python 环境与前端依赖。在项目根目录执行：

```powershell
# MySQL 已运行时无需重复执行；提示端口已占用时先确认现有进程。
.venv\Scripts\python.exe -X utf8 scripts/start_mysql.py
.venv\Scripts\python.exe -X utf8 scripts/start_dev.py
```

用户页：[http://localhost:5173](http://localhost:5173)；商家页：[http://localhost:5173/merchant](http://localhost:5173/merchant)。统一使用 `localhost`，与本地允许来源配置一致。

商家账号密码保存在本机 `.local/merchant-login.txt`，不会提交。基础安装与启停见[一阶段人工接待闭环说明](./docs/一阶段_人工接待闭环说明.md)，AI配置及验收见[网页接入说明](./docs/简化AI网页接入说明.md)。示例默认disabled、调用限制12次／1元；已有本机配置按用户后续授权取消次数与金额上限，详见[公网试用说明](./docs/本机公网试用说明.md)。实际运行配置与累计用量以本地配置和账本为准，本次未检查运行状态或更改配置。Key只保存在忽略的后端.env；账本、异常暂停、价格日期及长度保护继续保留。

## 技术与边界

- 前端：React＋TypeScript＋Vite，用户已确认。
- 后端：Python＋FastAPI，用户已确认。
- 数据库：MySQL，用户已确认。
- 访问方式：首轮约10人远程试用；先本地开发验收，再部署同一套应用。暂无服务器，可稍后租用，接受少量托管费用，平台与费用上限待定。
- 身份：用户免注册、浏览器保存会话凭证；单商家账号密码登录。
- 同步与附件：约两秒轮询，发送后立即刷新；一阶段仅文本，不上传或处理图片／视频。
- 托管平台、预算上限及生产备份方案：仍待确定。

访客用 HttpOnly Cookie 绑定自己的记录；商家必须接手后才能回复和结束。结束后新留言恢复普通咨询，保留用户主动选择；再次自动转交或点击“转人工”会开启下一轮交接并回到待处理，复用原会话，商家须重新接手。失败保留输入，同一消息重试不重复保存；用户接口不返回商家交接信息。

# 人工处理规则

确认日期：2026-10-13。用户已认可本规则。本文是下一步开发和验收依据；过期回复补发、进度查询及结束结果登记尚未实现。

## 接待状态与处理结果

人工进度使用「待接手」「处理中」「已结束」三个状态。客户转人工时进入待接手；商家点击接手后进入处理中；商家登记结果并结束时进入已结束。

接待状态、处理结果、消息送达分别记录。已结束不等于已解决，已解决也不等于结果已送达QQ。结束时必须明确选择「已解决」或「无法解决及原因」，记录可供客户查看的结果；不可用空白结果结束。

## 状态与动作

| 场景 | 确认规则 |
|---|---|
| 客户请求人工或系统转交 | 立即加入待处理，暂停AI；材料未齐不能阻止转交 |
| 商家查看会话 | 可以查看完整记录与内部摘要；仅查看不算接手 |
| 商家接手 | 进入处理中，开放人工回复；AI不插话 |
| QQ回复窗口有效 | 人工回复直接发送；工作台显示发送结果，不把平台接受写成客户已读 |
| QQ回复窗口过期 | 商家可以填写回复，保存为待发送；明确显示尚未送达 |
| 商家修改／取消待发回复 | 允许修改或取消。客户回来时只补发最新待发版本，不补发一串旧版本 |
| 客户再次发消息 | 有有效待发回复时发送最新版本；人工尚未结束时继续人工接待，不恢复AI |
| 客户发送“查询进度” | 仅返回商家已登记的状态和结果；不让AI猜测处理进展，也不输出内部摘要 |
| 商家结束处理 | 必须登记已解决或无法解决及原因；待发送结果仍保留，结束不能丢弃结果 |
| 结束后客户提出新问题 | 恢复AI接待；再次需要人工时开启新一轮交接，保留历史 |

回复窗口到期不自动结束人工处理，也不改变处理结果。客户再次发消息可以开启新的平台回复窗口，但不能被理解为之前的失败回复已送达。

结束后首次回来仍有待发送结果时，应先处理保留的结果，再按已结束规则接待新问题。“查询进度”本身只查询已登记事项，不自动开启新的人工事项。

## 待发回复与发送异常

待发回复属于对应的人工处理轮次。修改后只使用最新版本；已取消内容不发送。发送结果不明时保留待核对状态，不能为了补发而重复发送可能已经送达的内容。

“只补发最新版本”针对商家保存的待发回复；历史聊天保留，已送达消息不撤销。系统接手通知、旧AI回答和旧失败队列不会因此全部重放。

QQ发送还受次数、连接和平台拒绝等限制。新的回复窗口不保证发送成功；无法确认送达时不得标记成功。各类发送异常的技术重试与去重方案在实现时落实，不改动已确认的业务规则。

## 验收条件

| 编号 | 用例 | 通过条件 |
|---|---|---|
| H01 | 材料未齐时请求人工 | 成功转交，AI暂停，可继续补充文字 |
| H02 | 查看但未接手 | 状态不变，不允许人工回复 |
| H03 | 窗口有效时回复 | 显示真实发送结果，消息对应正确客户 |
| H04 | 窗口过期时回复 | 可保存，明确待发送，不误标已送达 |
| H05 | 连续修改待发回复后客户回来 | 只发送最新有效版本，旧版本不发送 |
| H06 | 取消待发回复后客户回来 | 已取消内容不发送 |
| H07 | 无结果或缺少无法解决原因时结束 | 拒绝结束，提示补齐结果 |
| H08 | 登记结果并结束，客户尚未回来 | 已结束和待发送可同时存在，结果不丢失 |
| H09 | 查询进度 | 只返回已登记状态与公开结果，无虚构进展及内部摘要 |
| H10 | 处理中客户回来／结束后新问题 | 前者继续人工，后者恢复自动接待；新交接不混用旧轮次结果 |
| H11 | 重复事件、重启及发送结果不明 | 保存结果不丢失，不重复补发，不假称送达 |

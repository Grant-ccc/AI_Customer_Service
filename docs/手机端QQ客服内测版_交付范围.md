# 手机端 QQ 客服内测版：交付范围

确认日期：2026-10-16。用户已接受本轮范围。当前工作分支为 `codex/mobile-ui-redesign`。

## 本轮目标

客户通过 QQ 私聊咨询，需要时转人工；单商家使用 Android 内测 App 查看、接手和回复，在原会话结束接待。用真实手机验证操作和异常，用可复现的启停、检查及备份恢复流程支撑小范围内测。

本文件规定这一轮做到哪里可以收尾；[MVP 功能清单](./MVP功能清单.md)继续记录项目全部能力和后续事项。本轮范围确认不代表验收已通过，也不代表已经正式上线。

## 本轮必须完成

| 编号 | 交付项 | 完成条件 | 当前证据与缺口 |
| --- | --- | --- | --- |
| M01 | QQ 咨询与转人工 | 客户 QQ 私聊能够咨询并申请人工；商家 App 显示正确客户及对应交接；等待与人工期间 AI 不插话 | 已有 QQ 实现及历史私聊验证；当前交付版本仍需与 Android App 连起来实测 |
| M02 | 手机人工接待 | 真实手机走通查看详情、接手、回复、结束、再次交接；关闭按钮常驻，聊天界面直接可接手；滚动和软键盘不遮挡常用按钮；系统返回与锁屏后恢复可继续操作 | 已有移动 UI 与浏览器／真实接口检查；浏览器视口检查不能替代手机键盘、系统返回和后台恢复验收 |
| M03 | 消息状态与异常 | 能区分等待、平台接受、失败、过期和结果未知；平台接受不写成客户已读；断网、确认丢失与恢复后不误标成功；重试不重复保存，结果未知不盲目重发 | 已有去重、投递状态和异常检查；当前版本仍需集中回归及 QQ 实际收发验证 |
| M04 | 内测运行与恢复 | 使用者能按说明启动、检查、停止本机数据库／网页／QQ 服务；能制作数据备份，并在独立恢复环境验证账号、会话与消息等关键数据可用；记录操作、结果和回退方式 | 已有启停、QQ 守护与检查工具；备份恢复流程和演练仍待完成，演练不得覆盖现有业务数据 |

## 本轮暂缓

- 手机系统推送、锁屏主动提醒及超时催办。本轮需要打开 App 查看待处理；锁屏恢复操作与锁屏收到通知是两项不同能力。
- QQ 回复窗口过期后的独立待发结果保存、修改／取消与自动补发。
- 客户查询处理进度、结束时登记处理结果。
- 正式服务器部署及应用商店发布。本轮仍是依赖电脑和公网入口在线的内测。

前三项作为后续版本事项保留；[人工处理规则](./人工处理规则.md)中已确认的规则不作废。本版“结束”只代表结束接待，不代表问题已解决，也不代表结果已送达；不能宣称已实现该规则中的结果必填和补发流程。

现有网页入口、摘要、发货查询与发货表等功能保留，不因本轮收缩而删除；不为其扩展新功能。影响本轮接待、权限或数据正确性的回归问题仍须修复。历史模拟口径和 AI 质量限制继续明确，不因本轮验收通过而推导总体准确率或业务收益。

## 收尾与变更规则

1. 下一步逐项整理 M01—M04 的验收用例、运行版本、预期结果、实际结果和问题记录。现有记录见[移动端验收](./移动端验收记录_2026-10-14.md)，不可自动作为新版本全部通过的证据。
2. 只有上述完成条件均有证据、阻断接待／权限／数据的问题已解决，才可标为本轮验收通过。尚缺手机或外部条件的项目记录为待验收／受阻，不写成通过。
3. 发布内测包时记录代码版本、APK 来源和签名／升级限制、网页／后端是否采用对应版本，以及启动和恢复说明。推送代码、构建 APK、更新运行服务分别记录。
4. 新需求先记后续清单；需要纳入本轮时，重新确认范围与验收条件。当前只确认范围，未授权购买服务器、申请企业资质或发布正式应用。

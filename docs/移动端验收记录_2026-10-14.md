# 移动端接待与异常场景验收

2026-10-14。范围：独立 MySQL 测试库、真实 FastAPI 接口与移动尺寸的 Chromium 浏览器。没有连接 vivo 设备；没有向真实 QQ 客户发送测试消息。以下结果不能替代 Android 实机及 QQ 客户端收发验收。

## 结果

| 项目 | 结果与证据范围 |
| --- | --- |
| 登录 → 访客转人工 → 商家接手 → 回复 | 真实接口通过；回复到达独立访客浏览器，未验证 QQ 客户端到达 |
| 接口已保存消息，但发送确认丢失 | 使用真实接口接受后中断响应，再重试；MySQL 中同一回复只有一条 |
| 断网发送与恢复 | 草稿保留；返回列表后重进仍保留，联网后提交成功 |
| 长聊天记录 | 插入 12 条长消息；阅读旧记录时新消息不会强行拉到底部，显示新消息入口，查看后真实未读状态更新 |
| 输入区可视性 | 390×420 浏览器可视区域内输入框和发送按钮仍在屏幕内；不是手机软键盘实测 |
| 横屏 | 首次发现 844×390 触屏视口误切桌面三栏、返回按钮消失；修复后保持移动聊天布局并通过验收 |
| 结束处理 → 再次咨询 → 再次转人工 | 真实接口通过，交接轮次为第 2 轮，浏览器返回与重进正常 |
| 现有移动界面回归 | 模拟 API 检查覆盖筛选计数、交接详情折叠／关闭、结束确认及失败处理等；与真实接口结果分开记录 |
| QQ 后端通道 | 19 项后端自动检查通过，包含转人工、工作台回复队列与投递异常；不是平台真实收发验收 |
| 浏览器前后台切换 | 本次无头环境未提供可验证的页面可见性切换，未判定通过 |
| vivo 键盘、系统返回键、锁屏及后台恢复 | 无连接设备，未测试 |
| QQ 私聊 → Android App 接手 → QQ 实际收到 | 无手机控制通道，未测试；机器人进程运行不等于本轮收发验证通过 |

## 横屏修复

移动布局除窄屏外，也匹配低高度的触屏视口，避免手机横屏因为宽度超过 820px 而切换桌面接待台。鼠标桌面浏览器仍按原宽度规则使用三栏界面。

## 复现

需要项目虚拟环境中的 Playwright、本机 Edge 和项目 MySQL。QQ 后端检查会清理专用测试库，因此与真实接口浏览器验收顺序运行，不并发运行。

```powershell
.venv/Scripts/python.exe -X utf8 -m pytest backend/tests/test_qq.py -q
.venv/Scripts/python.exe -X utf8 scripts/start_dev.py --test-db
.venv/Scripts/python.exe -X utf8 scripts/e2e_mobile_live.py
```

浏览器脚本先确认访客凭据存在于专用测试库，再发送测试消息；拒绝把正常业务服务当成测试服务。使用已知的测试账号，不读取或输出真实商家密码。所有消息为带唯一标记的测试文本，保留在测试库内。

结构化结果与截图保存在忽略目录 `.local/mobile-live/`。UI 模拟验收结果位于 `.local/mobile-ui/`。本次未修改 Android 工程、通知权限或生产数据库。

剩余工作需要连接可控制的手机，或由使用者在设备上完成上述未测试项目，再补充结果。

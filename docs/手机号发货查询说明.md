# 手机号发货查询

用户确认：不使用平台订单号，按用户私聊提供的完整收件手机号查询发货表。

## 商家操作

在工作台点击「发货表管理」，上传 xlsx，检查新增／更新数量及前5条脱敏预览，再点击「确认导入」。预览不修改发货数据，30分钟后失效。

以快递单号作为记录标识。重复上传更新该单号对应手机号和更新时间；新表遗漏的历史记录保留。表内单号重复、手机号无效或号码列冲突时整份拒绝，指出工作表及行号，不静默跳过错误记录。

识别第一行表头中的「快递单号」及「手机／手机号／固话」。用户提供的表中「手机」为空，「固话」实际存放手机号，因此可直接导入。空白工作表忽略。每次最多5MB、5000行。

只保存完整手机号、快递单号和导入更新时间，不导入姓名、地址、支付信息或不明确的商品规格。手机号是匹配条件，不构成身份认证；知道该号码的人也可以查询该号码下的单号。本版不返回姓名、地址或完整电话。

## 用户操作

QQ 私聊或网页发送「查发货」，机器人提示提供完整手机号；也可直接发送11位手机号查询。同一手机号最多直接展示10条匹配发货记录，更多记录转人工核实。

群内查询引导私聊，不公开返回单号。等待人工／人工接待中不自动抢答。发送「转人工」复用现有交接流程。

返回快递单号及上传更新时间，明确这是商家上传的发货单记录，不等于实时物流轨迹、签收状态或订单状态。无匹配时提示核对号码或转人工，不能据此断定未下单／未发货。当前没有平台订单号及可靠规格／数量，故不提供相应查询。

本地查询不调用付费模型；后续问答及真实摘要发送给模型前隐藏完整手机号。聊天记录中的原用户消息仍保留，供商家核实。

原始发货表和个人数据不得提交 Git。接口要求商家登录、有效来源及 CSRF 凭据；预览确认重复请求不会重复新增记录。

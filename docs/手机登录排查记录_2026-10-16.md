## 现象与执行结果

| 来源 | 操作／现象 | 结果与边界 |
| --- | --- | --- |
| 用户手机反馈 | App 与系统浏览器都能显示登录页，但提示连接中断 | 页面可加载不能证明后续 API 请求正常；未获取手机网络请求记录 |
| 本机只读检查 | 检查数据库、API、QQ、本机页面及 App 配置的 HTTPS 入口 | 数据库／API 正常，QQ 已连接；网页资源与当前构建一致，健康接口返回 200 |
| 公网 API 诊断 | 无凭据会话 GET；空登录请求 POST；使用本地已有凭据独立登录、读取会话并退出 | 分别返回预期的 401、422、200；响应为 JSON。独立诊断会话退出 200，不修改密码、不退出用户自己的会话 |
| 公网浏览器诊断 | 全新 Edge 上下文、390×844 视口，实际点击登录并进入工作台 | 登录、会话列表、QQ 状态请求均返回 200，未见请求失败、页面脚本错误或连接提示；登录后约 2.1 秒进入工作台。它是电脑浏览器检查，不代替 Android WebView |
| 用户手机复试 | 切换 Wi-Fi／移动数据后再次登录 | 用户确认“切换后可以登录了”。未明确切换方向，以及 App 与浏览器分别复试的结果，不补填这些信息 |

本轮未调整业务代码、密码、来源白名单或证书校验。公网浏览器诊断只读取工作台和状态，不接手、回复或结束客户会话；诊断完成后已退出其独立会话。

## 判定与下一步

登录已在用户切换网络后恢复，也有本机独立公网登录证据。现象与手机到公网入口的网络路径有关，但尚不能区分 DNS、网络策略、穿透线路或暂时性故障；不能宣称根因已定位或原网络已修复。

M02-01 仅新增“手机登录可用”的用户反馈，未登录权限、对应客户、App／APK 版本等仍按清单核验。M03-06 仅新增网络切换恢复现象，不代替手机断网发送与所有通道状态的验收。

下一个手机步骤：在商家 App 登录到会话列表，用专用测试 QQ 私聊机器人发送“转人工”，返回 App 核对对应待接手会话。尚未记录该步骤的执行结果。

如再次出现连接中断，先记录发生时间、当时网络、App／浏览器及具体提示，再对照服务端请求。无需为本次现象重置密码或放宽来源与证书保护。

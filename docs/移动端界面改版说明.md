# 移动端界面改版

2026-10-14，在 `codex/mobile-ui-redesign` 实现商家移动端界面。沿用米白 `#f4f1e9`、纸白 `#fffdf7`、墨绿 `#284e43` 和酒红 `#7f392e` 配色。

## 页面与现有功能

- 820px 及以下使用独立移动端工作台，底部为「消息、工作台、我的」。更宽的屏幕保留三栏接待台。
- 消息页合并接口已有的待处理与已结束会话，按最近更新时间排序。支持全部、未读、待接手、接待中、已结束筛选，以及会话编号／消息预览搜索；搜索可与状态筛选组合。这里的「全部」仅指人工接待接口返回的会话，不包含尚未转人工的所有 QQ 聊天。
- 聊天页独立展示，提供返回列表、交接详情、人工接手、文字回复及 QQ 投递状态。交接摘要放在详情弹层，接手与结束均可在聊天页直接操作。
- 交接弹层顶部标题与关闭按钮常驻，滚动长摘要仍可关闭。待接手会话在聊天页底部显示完整宽度的「接手会话」按钮；接手成功后直接显示回复输入区，无需先打开交接详情。
- 针对手机反馈，交接弹层采用固定高度的外框与独立正文滚动区，标题不属于滚动区，不再依赖 sticky。回归检查在 390×844 和 360×640 视口使用实际滚动事件，确认正文确实到达底部、关闭按钮位置不变且仍可点击。
- 接待中的聊天页右上角提供「结束处理」，交接详情内保留原入口，两处均先确认。取消不发请求；结束失败在确认弹窗提示并允许重试，不提前显示已结束。
- 工作台分别显示待接手、接待中会话数量，点击数量直接进入对应筛选；最多展示五个事项，待接手排在接待中之前。保留发货表管理与已结束会话入口。数据使用现有接口，不新增审核回复、常用回复或机器人配置能力。
- 我的页提供接待说明、最近同步时间、退出登录。顶部「已同步」仅表示最近一次会话请求成功，不表示 QQ 机器人在线。
- 回复草稿按会话暂存在当前页面内存，返回列表再进入后保留；刷新、退出或登录失效后清除。失败回复再次进入同一会话重试时沿用发送标识，保持现有幂等语义。
- 区分「提交到工作台」与「QQ 平台投递」。提交未确认时保留草稿、提供同一标识的重试；已入库的消息在气泡下显示等待发送、发送中、平台已接受、窗口过期、次数用尽、失败或结果待核对。「平台已接受」不代表客户已读。异常投递提供处理提示及复制回复；剪贴板不可用时显示可长按复制的文字。复制不会触发发送，结果不明的投递不自动重发。
- 仅打开聊天记录时确认已读，浏览消息列表／工作台不会因为后台详情轮询确认已读。

## 验证

`npm.cmd --prefix frontend run build` 执行 TypeScript 检查与生产构建。

`scripts/e2e_mobile_ui.py` 使用 Playwright 与隔离的模拟 API 验证导航、混合状态会话的搜索筛选与计数、工作台优先排序、同步错误保留列表、发货表入口、人工接手、草稿保留、失败重试的发送标识、QQ 七种投递状态、复制及剪贴板降级、结束确认的取消／失败／重试、浏览器返回、退出登录，以及 320／360／390／430／768px 布局和桌面接待台。测试不发送真实 QQ 消息，也不写入数据库。

在项目根目录的一个终端启动前端：

```powershell
npm.cmd --prefix frontend run dev -- --port 5175
```

在另一终端执行（需要项目虚拟环境中的 Playwright 与本机 Edge）：

```powershell
.venv/Scripts/python.exe scripts/e2e_mobile_ui.py
```

截图位于忽略目录 `.local/mobile-ui/`，不提交到仓库。

## 手机验收

当前 Android 内测 App 加载远程商家网页；本次修改网页前端，未更改原生工程及域名。远程网页采用新构建后，App 重新打开即可加载；代码推送不等于远程服务已更新。

浏览器检查不能代替 vivo 实机验收。需在设备上继续确认键盘弹出时输入区、长消息滚动、系统返回键、顶部／底部安全区域、xlsx 文件选择与 QQ 实际收发。本次未部署线上服务，未增加系统通知或后台常驻功能。

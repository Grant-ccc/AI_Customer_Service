# QQ 官方机器人接入（首轮文字验证）

本分支 `codex/qq-integration` 在现有客服系统上新增 QQ 官方 WebSocket 通道。
无需安装 OpenClaw，也不更换现有模型、Prompt 或网页登录方式。

## 当前范围

- 接收 QQ 私聊与群内 @机器人消息；忽略群内普通消息。
- 同一 QQ 用户私聊复用会话；群聊按群和成员分别隔离，不把其他成员的记录送给模型。
- 私聊复用现有自动／主动转人工、交接摘要及网页商家工作台。
- 群内订单、退款、换货等请求引导私聊；模型提出人工交接时也只引导私聊。
- 商家接手后，工作台回复通过发送队列发回对应 QQ 私聊；人工期间暂停 AI。
- 本轮仅文字；附件不下载、不保存、不声称已审核，明确提示用户先文字描述。
- 已增加 Excel 发货表导入与完整收件手机号查询，详情见[手机号发货查询说明](./手机号发货查询说明.md)。私聊直接返回表中快递单号，不调用模型；群聊引导私聊。当前没有平台订单号和实时物流状态。

## 本地配置与启动

在平台开发设置添加自己和朋友为开发体验用户，配置一个测试群。
保持 WebSocket，公开私聊／群聊和搜索开关可以先关闭。

在 `backend/.env` 填写（实际密钥不提交）：

```dotenv
QQ_APP_ID=你的AppID
QQ_APP_SECRET=你的AppSecret
```

先保持原 MySQL 和网页服务运行，再从仓库根目录执行：

```powershell
.venv\Scripts\python.exe -m pip install -r backend/requirements.lock.txt
.venv\Scripts\python.exe -X utf8 scripts/start_qq.py --check
.venv\Scripts\python.exe -X utf8 scripts/qq_service.py start
```

`--check` 只验证凭据和网关访问，不证明事件权限及消息发送成功。
运行 `scripts/qq_service.py status` 确认连接后再开始手机客户端测试。日常使用可双击 `scripts/start-qq.cmd`、`scripts/check-qq.cmd`、`scripts/stop-qq.cmd`。主动停止使用 `scripts/qq_service.py stop`；不要仅关闭启动命令窗口来判断后台通道已停止。
异常恢复、连续失败暂停、日志和电脑重启后的使用方式见[QQ本地守护与启停说明](./QQ本地守护与启停说明.md)。原 `scripts/start_qq.py` 仍可用于前台调试，此模式按 Ctrl+C 停止且没有进程守护。运行中的通道占用文件锁时，`--check` 会拒绝重复进入，改用守护的 `status` 查看状态。
本地文件锁防止同一目录重复启动；当前不支持多机器同时运行同一机器人。
WebSocket 由本机主动连接平台，消息收发无需公网回调；外部访问网页工作台仍需公网入口。

AI 使用原 `AI_WEB_MODE`，`mock` 是明确标记的流程模拟，`deepseek` 是付费真实调用。
AI 原有价格快照、失败未知账本及额度保护继续生效，未取消或绕过。
价格快照过期时会提示 AI 暂未能回复，此时仍可发送“转人工”；需核实价格后更新本地日期。
QQ 与网页进程共享数据库，但各自恢复自己的中断任务。

## 发送限制与故障

使用用户消息 ID 被动回复。按当前在线官方说明，私聊 60 分钟／4次，群聊 5分钟／5次。
机器人提示、AI回答、商家接手及回复等均消耗次数；用户新发消息开启新的回复窗口。
超时或次数用尽时不会偷偷改成主动发送；商家需让用户重新发消息。
历史待发消息仍绑定原用户消息，不会在用户下一次提问时自动补发旧答案。
发送队列持久化，事件重放去重；网络超时、崩溃时结果不明的发送不自动重发。
工作台可看到“QQ发送失败”事件。消息标记 sent 只代表平台接受，不代表用户已读。
短暂断线尝试恢复会话并补收事件；进程关闭期间的所有消息不保证补齐。

## 人工验收

1. 私聊问商品问题，收到自然回复，再追问，验证上下文。
2. 群中两个人分别 @提问，验证会话不串；普通闲聊不触发。
3. 群内问订单或转人工，收到私聊指引；不在群内建立售后人工会话。
4. 私聊发送“转人工”，网页出现 QQ 待处理会话与摘要。
5. 商家接手、回复，手机收到对应消息；用户补充时 AI 不抢答。
6. 商家结束后，用户新留言恢复 AI；再次转人工开启新一轮交接。
7. 发图片，明确收到仅文字说明；工作台不会显示“已收到材料”。
8. 断网重连、发送拒绝与回复窗口过期时检查工作台提示，确认无重复发布。

真实联网收发必须有本地密钥、平台事件权限和测试用户参与；自动测试不代替这些验收。

开发验证：58 项后端检查通过（含 19 项 QQ 检查），前端 TypeScript 检查与生产构建通过。
QQ 检查覆盖会话隔离、重放去重、同秒连续消息、人工暂停、群内转交限制、附件说明、
发送超时／次数／未知状态、凭据刷新及 WebSocket 登录／恢复。
真实 QQ 私聊已完成商品问答、转人工、商家回复、结束后恢复问答及再次交接验证；群聊仍需群内测试。手机号查询已通过自动检查，真实 QQ 查询需在导入发货表后验收。

# 花窗伞客服 MVP 功能清单

更新时间：2026-10-13。当前实现分支：`codex/qq-integration`。

本清单是当前功能状态的统一入口。依据已确认的业务讨论、当前代码及已有验证记录整理；未重新执行全量验收。旧 PRD 保留初始方案，旧测试结果不自动视为当前版本的验收结果。

## 1. 当前目标与范围

首版服务花窗伞业务，单商家账号。售前回答商品、使用问题并指引购买平台，不代下单；售后先了解问题、提醒材料，再交商家判断。客户可通过 QQ 私聊或网页咨询；商家在网页工作台处理。QQ群仅接收 @机器人消息，涉及个人订单和售后处理时引导私聊。

当前订单相关能力是「上传发货表后，凭完整收件手机号查快递单号」，不要求客户提供平台订单号，不代表接通实时订单或物流系统。

状态含义：**已实现**表示已有代码和相应检查；**待验收**表示仍缺指定场景的实测或业务评分；**待开发**表示已讨论方向但尚无实现；**待确认**表示规则尚未共同定稿。没有用功能数量计算完成率，也不把检查通过等同于业务效果达标。

## 2. 已实现功能与验收缺口

| 编号 | 功能 | 当前实现与证据 | 尚需验收或明确的边界 |
|---|---|---|---|
| F01 | 商品与使用问答 | 固定公开 Prompt＋本轮对话，真实模型自然回复；已有网页和 QQ 私聊问答验证 | 按业务测试题重新评估准确性、材料提醒及转人工判断；没有总体正确率结论 |
| F02 | 购买指引 | 业务范围为说明商品并指引既有购买平台，不创建或支付订单 | 核对当前购买入口与历史业务日期，避免历史演示被理解为当前开售 |
| F03 | 网页客户入口 | 文字聊天、历史记录、免注册会话及转人工按钮；已有浏览器闭环验证 | 朋友手机的完整流程需纳入本轮统一验收；换浏览器不自动继承会话 |
| F04 | QQ 私聊入口 | 官方机器人收发，复用客户会话、问答与人工流程；真实私聊人工闭环已验证 | 发货查询及新增消息标题仍需手机 QQ 实测确认 |
| F05 | QQ 群入口 | 接收 @消息，按群与成员隔离上下文，个人订单与售后引导私聊；自动检查通过 | 真实群聊两名用户隔离、普通消息不触发、隐私引导待验收 |
| F06 | 主动／自动转人工 | 明确请求和网页按钮可转交；复杂售后可由模型提出转交；等待及人工期间暂停 AI | 真实业务的漏转人工和不必要转人工待评分；材料不齐不能阻止转交 |
| F07 | 内部交接摘要 | 诉求、已知情况、尝试操作、材料情况，附用户原话依据；失败不阻塞接手 | 语义准确性、关键诉求遗漏待业务审查；转交后补充不自动进入旧摘要 |
| F08 | 网页商家工作台 | 单账号登录，待处理／已结束、未读标识、记录与摘要、接手、回复、结束 | 商家实际使用的操作耗时和漏处理问题待记录；没有后台手机推送 |
| F09 | 结束后继续咨询 | 保留历史，新问题恢复自动接待；再次转人工开启新一轮交接 | QQ 私聊已有真实验证，后续变更需继续保留回归场景 |
| F10 | Excel 发货表管理 | 上传 xlsx、脱敏预览、确认导入；按快递单号新增／更新，保留未出现的旧记录；290条真实记录已导入 | 错误导入的纠正／删除、历史数据保留期限尚未定稿；不是完整订单管理 |
| F11 | 手机号发货查询 | 完整11位收件手机号直接查数据库，不调用模型；返回单号及表更新时间；网页／QQ路径自动检查通过 | QQ真实查询待验收；号码不是身份认证，知晓号码者可查单号；无实时物流轨迹 |
| F12 | 消息来源标识 | 网页及 QQ 自动消息带 `[智能回复]`，系统通知带 `[系统消息]`；构建及19项QQ检查通过 | 人工消息仍不加前缀，`[商家回复]`仅为建议；QQ气泡颜色不由本项目控制 |
| F13 | QQ 发送结果 | 工作台显示平台接受、过期、次数用尽、失败或结果待核对；自动检查通过，已有实际过期案例 | 平台接受不等于用户已读；过期消息仍绑定原消息，不自动补发 |
| F14 | 本机公网试用 | HTTPS穿透至本机网页，已有朋友试用及入口检查 | 电脑、节点和服务须在线；不是正式生产部署，没有持续可用性承诺 |
| F15 | 会话与异常保护 | 登录与会话隔离、内部摘要隔离、消息去重、旧AI回复抑制、持久任务和QQ队列已有检查 | 正式上线前仍需补齐备份恢复、监控及实际断线场景验收 |
| F16 | AI 调用管理 | 本机按用户要求取消次数与金额上限，账本、异常暂停、价格日期和长度保护仍保留 | 仍由模型服务商计费；无额度限制不代表持续可用或免费 |

| P04 | 手机商家 App | 后续候选，未开发 | 先确认目标手机、安装与推送资格，再决定是否投入 |
| P05 | App关闭后的vivo推送 | 可行性调研阶段，未接入 | 厂商通道申请及上架条件、通知权限与实机送达验证 |
| P06 | 正式服务器部署 | 后续候选，未部署 | 服务器与域名、部署方式、备份、恢复和运行成本 |

QQ的60分钟回复窗口不能靠修改本地配置延长到24小时。客户沉默24小时后由机器人主动提醒，当前未确认有可用官方能力，不作为MVP交付项。定时提醒商家是另一个方向，尚未开发。

## 4. 当前不包含

- 普通微信群自动读消息或群内机器人客服；微信／企业微信接入仍没有落地。
- 下单、支付、自动退款／换货／赔偿审批及实时物流查询。
- 附件上传、照片／视频审核。当前QQ附件仅收到文字说明，不下载材料。
- 多商家、多客服分配及客服绩效系统。
- 可播放的完整商品视频资源；原方案允许占位，当前不宣称资料齐备。

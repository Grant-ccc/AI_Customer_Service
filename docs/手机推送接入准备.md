# 手机转人工推送接入准备

2026-10-14。用户已授权接入手机提醒；当前没有 vivo 开发者账号或已开通的推送应用。

## 当前结果与限制

后端在统一的 `open_handoff` 入口保存 `merchant_alerts` 事件。网页按钮、文字主动申请、模型转交和 QQ 私聊转人工共用入口。事件与交接共用数据库事务，回滚不会留下提醒；交接 ID 为主键，同一轮只记录一次，补充文字不重复创建。新表由现有 `ensure_schema` 创建，不重写原有表或回填历史交接。

未来发送器可用 `eligible_alerts` 查询尚未接手、尚未结束且仍在有效期的事件。有效期暂为 10 分钟，仅用于避免开通后重放旧提醒，不改变待接手会话的状态。过期提醒记录保留，待接手事项仍保留在工作台。后续接入发送器时，还必须增加每台设备的发送状态、并发领取、厂商回执与失败处理，不能仅凭事件存在判定已发送。

商家登录后可读取 `GET /api/merchant/notifications/status`；当前明确返回 `state=not_connected`、`background_push_available=false`。`pending_events` 是有效事件数，不是手机收到的数量，不触发任何外部消息。

本步没有集成 vivo SDK、注册手机、申请通知权限、调用推送 API 或生成支持推送的 APK。后台、锁屏、划掉 App 后目前仍不能收到通知。代码提交不等于运行中的 API/QQ 已重启采用新代码。

验证：独立 MySQL 测试库执行提醒、人工交接、QQ 与主动／模型转人工相关测试共 55 项通过。覆盖重复／并发申请、QQ 重放、事务回滚、接手与下一轮、有效期边界和商家鉴权；未向任何真实设备发测试消息。

## 账号开通时使用的信息

| 项目 | 值／处理方式 |
| --- | --- |
| 应用名称 | 花窗伞商家 |
| Android 包名 | `com.huachuangsan.merchant`，必须与平台注册包名一致 |
| 工程 | `mobile/android`，Capacitor Android |
| 当前用途 | 商家内测，客户转人工后提示商家接待 |
| 通知文案建议 | 标题“有新的人工接待请求”，正文“请打开花窗伞商家查看并处理” |
| 签名 | 当前为云构建 debug 包；接入前确定稳定签名，核对平台要求的证书指纹，不能使用随构建变化的临时签名注册正式应用 |

1. 用户本人登录 [vivo 开放平台](https://developers.vivo.com/)，完成开发者认证，按后台要求创建应用。平台审核、账号类型及资料要求以后台实际展示为准。
2. 申请目标应用的推送服务。官方说明要求创建应用审核通过后启用推送，见 [vivo 推送产品说明](https://developers.vivo.com/doc/d/6b683b474cf64fdab1a0738035c8868e) 与 [官方接入流程入口](https://dev.vivo.com.cn/documentCenter/doc/281)。未上架应用测试设备限制可参阅 [腾讯云 vivo 通道配置](https://cloud.tencent.com.cn/document/product/269/132305)；该文档用来核对厂商条件，不代表项目已选择腾讯云 IM 或需购买 IM。
3. 开通后确认 AppID、AppKey、AppSecret 和测试设备配置可用。密钥不要贴聊天、写业务文档、提交 Git 或内置 AppSecret 到 APK；服务端秘密留在受忽略的本地环境配置，构建参数另行安全配置。

## 开通后继续完成的工作

1. 取得官方当前 SDK 与集成说明，增加用户同意后的初始化、通知权限、设备 RegID 注册；Android 13 及以上按 [系统通知权限说明](https://developer.android.com/develop/ui/views/notifications/notification-permission) 处理。
2. 用现有商家登录和 CSRF 校验绑定设备；退出登录和账号切换解绑，过期登录的设备不继续泄露接待信息。
3. 增加后台发送器与每设备发送记录；发送前复查交接状态和有效期。厂商受理、手机到达、点击分别记录；发送结果未知时不盲目重试，防止重复响铃。
4. 通知点击只携带交接／会话标识，打开后仍校验登录。已接手或结束时展示当前状态，不自动执行接手。通知不携带客户消息、QQ 标识、订单、手机号等内容。
5. 重新构建 APK，在登记的 vivo 手机上验收：前台、后台、锁屏、划掉 App、断网重连、拒绝通知权限、退出登录、交接被另一设备接手。不承诺系统强行停止应用后仍能送达。

SDK 初始化前的告知与同意要求参见 [vivo 推送 SDK 隐私安全说明](https://developers.vivo.com/doc/d/23807c559e844cbeb06049ee69e71833)。实际集成时再落实到 App 内交互。
